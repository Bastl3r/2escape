# Project instructions

- keep all business code and markup in a single index.html, except the puzzle framework (puzzles.js), which is intentionally separate; puzzle types, puzzle UI, handbook entries and puzzle parameterization belong there
- puzzle generation must stay seed-stable: append new draws/params at the end of the schedule in puzzles.js, never in the middle
- do not implement features lacking clear requirements
- if implementation can be achieved in multiple ways provide options and outline benefits of each option
